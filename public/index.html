Install the chart

Add the repository, update Helm metadata, and install KubeOps Insight into its own namespace.

1. Add the repository

helm repo add kubeops-insight https://yosoyfunes.github.io/kubeops-insight
helm repo update

2. Install the chart

helm upgrade --install kubeops-insight kubeops-insight/kubeops-insight \
  --namespace kubeops-insight \
  --create-namespace

Repository URL

https://yosoyfunes.github.io/kubeops-insight

Metrics Server is optional. If it is not available in the cluster, the dashboard degrades metrics views to an unavailable state instead of failing.

Expose the dashboard

Forward the frontend service locally, then open the UI and sign in with the generated or configured credentials.

Port-forward

kubectl -n kubeops-insight port-forward svc/kubeops-insight-kubeops-insight-frontend 5173:80

Read the generated password

kubectl -n kubeops-insight get secret kubeops-insight-kubeops-insight-auth \
  -o jsonpath='{.data.password}' | base64 --decode

Open http://localhost:5173 and sign in as admin unless you supplied different credentials.

What the chart provides

Operational coverage stays grounded in live cluster evidence and read-only investigation flows.

Live Kubernetes reads

Pods, deployments, services, events, PVCs, ingresses, workloads, findings, and metrics summaries.

Bounded investigation

Read-only diagnostics and AI analysis operate on curated Kubernetes evidence instead of shell access.

Production defaults

Authentication required, read-only RBAC, hardened pod settings, NetworkPolicy, PDB, and optional OIDC.

Dashboard access requires login. The chart generates initial local credentials unless you provide an existing Secret. Amazon Bedrock is the default AI provider, and OpenAI-compatible chat completions are also supported through Secrets.

Common chart options

These values cover the most common install variations without changing the repository flow.

Use case Values
Install Metrics Server --set metrics.metricsServer.install=true
Enable ingress --set ingress.enabled=true --set ingress.hosts[0].host=kubeops.example.com
Use Bedrock --set llm.provider=bedrock
IRSA role annotation --set serviceAccount.annotations.eks\.amazonaws\.com/role-arn=arn:aws:iam::123456789012:role/KubeOpsInsightBedrockIrsaRole
Agent limits --set llm.agent.maxCycles=5 --set llm.agent.timeoutSeconds=30
OIDC login --set auth.oidc.enabled=true plus issuer, client ID, redirect URI, and Secret values.

Security posture

KubeOps Insight is intentionally read-only. It is designed to help operators investigate clusters without adding mutating automation.

Read-only RBAC

The backend reads cluster state and pod logs. Mutating Kubernetes actions are not enabled by default.

No shell execution

Investigations use curated Kubernetes API tools and bounded evidence collection rather than arbitrary commands.

Hardened workloads

Chart defaults include non-root execution, read-only root filesystem, NetworkPolicy, and PodDisruptionBudget templates.
